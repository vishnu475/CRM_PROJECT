2 Project Summary

2.1 Purpose of the Project

The Enterprise CRM, HRMS & ERP Management Platform is an all-in-one, multi-tenant capable business operating platform. It bridges the deep operational gaps between customer acquisition, workforce administration, and financial accounting. By replacing multiple disconnected third-party tools, the platform acts as the organizational single source of truth across 25 dedicated user interfaces and 41 backend API routers.

2.2 Business Problem It Solves

Fast-growing startups and enterprises frequently run into severe operational bottlenecks caused by software fragmentation. Organizations typically maintain separate SaaS subscriptions for CRM, payroll calculation, attendance tracking, project delivery, and accounting. This causes:

  • Data Synchronization Latency: Sales teams win deals, but operational teams must manually re-create client projects, quotes, and billing ledgers.
  • Attendance & Payroll Disconnect: Manual export of punch-clock spreadsheets into payroll results in inaccurate Loss-of-Pay (LOP) calculations and non-compliance with statutory tax deductions.
  • Excessive Subscription Costs: Compounding per-seat monthly subscription fees drain operational cash flow.
  • Audit & Access Exposure: Lack of centralized role-based access control creates severe security risks and prevents transparent compliance audits.

This platform directly solves these problems through an integrated dual-PostgreSQL database architecture, automated database triggers, real-time WebSocket state distribution, and standardized RESTful services.

3 Business Context

3.1 Why Was This Project Built?

The system was conceived and engineered to establish sovereign technological independence and operational efficiency for high-velocity modern organizations. When an organization scales past 50 employees, disconnected spreadsheets and disparate SaaS solutions fail to provide timely data. A unified ERP was built to eliminate manual human data transfers, enforce statutory legal compliances programmatically, and provide real-time executive visibility into organizational profitability.

3.2 Core Problems Solved

  1. Lead-to-Cash Workflow Automation: Converting a closed-won sales lead automatically creates a registered Customer profile, spawns a Delivery Project with predefined milestones, and enables instant quotation generation without duplicate data entry.
  2. Biometric-to-Payslip Automation: Punch events captured by the biometric kiosk or employee web interface stream directly into the attendance ledger. At month-end, the payroll engine programmatically evaluates worked days, unapproved absences, statutory PF/ESI caps, and LOP deductions to yield locked payslips.
  3. Immutable Enterprise Auditability: Every financial ledger journal entry, customer status update, and credential modification is logged with actor identification, client IP, and UTC timestamps.

4.1 Presentation Tier

Built as a responsive Single Page Application (SPA) leveraging React 18, TypeScript, and Tailwind CSS. State is managed centrally via the AppContext provider, decoupling UI components from network requests and ensuring optimistic UI updates.

4.2 Application Tier

An Express.js server operating under native ES Modules ("type": "module"). It processes incoming requests through a strict middleware chain: CORS verification, rate-limiting on sensitive authentication routes, JWT signature verification, and dynamic module-level authorization checks.

4.3 Persistence Tier

Data persistence is divided into two separate PostgreSQL instances: HRMS and CRM. This dual-pool architecture guarantees complete data isolation between internal workforce data (salaries, biometric logs, HR policies) and external client operations (deals, pipelines, invoices).

Strategic Rationale Behind Key Technology Choices

  • Raw Parameterized SQL over ORMs: Using parameterized node-postgres queries eliminates ORM performance overhead, prevents N+1 query bottlenecks, and allows utilizing native PostgreSQL triggers for automatic timestamping and attendance duration math.
  • Dual Database Isolation: Isolates sensitive employee compensation and biometric data from sales CRM records, allowing independent database backup, scaling, and access auditing.

6 Major Modules

1. HRMS — Core Employee Lifecycle HRMS DB

Purpose: Comprehensive administration of organizational structure and employee records.

Responsibilities: Onboarding, employee profile maintenance, role assignment, departmental classification, branch allocation, and exit status transitions.

Main Features: Auto-generated sequential employee codes (EMP-001); emergency contacts; PAN/Aadhaar compliance fields; multi-branch infrastructure; one-click employee status toggling (Active, On Probation, Notice, Terminated).

Dependencies: employees, departments, designations, branches tables.

2. Attendance Management & Biometric Kiosk HRMS DB

Purpose: Accurate recording of daily work hours, biometric punch events, and shift compliance.

Responsibilities: Enforcing shift timings, tracking biometric inputs, computing late marks, overtime calculation, and providing a full-screen interactive Kiosk interface.

Main Features: Fullscreen kiosk mode with PIN authentication and webcam visual verification; automated calculation of daily work hours via database triggers (clock_out - clock_in); shift master configuration; real-time admin roster updates via WebSockets.

Dependencies: attendance_logs, shifts, employees, ws WebSocket broadcast.

3. Leave Management Engine HRMS DB

Purpose: Digital administration of employee time-off, statutory leave entitlements, and approvals.

Responsibilities: Balance decrementing, leave history tracking, multi-level manager approval, and holiday calendar integration.

Main Features: Configurable leave quotas (Casual Leave - CL, Sick Leave - SL, Privilege Leave - PL); automated balance checks preventing negative balances; real-time approval/rejection triggers; approved unpaid leaves automatically flagged as Loss of Pay (LOP) for payroll processing.

Dependencies: leave_requests, leave_balances, employees, payroll_runs.

4. Central Payroll Engine HRMS DB

Purpose: Autonomous, compliant payroll calculation, payslip delivery, and statutory tracking.

Responsibilities: Generating gross-to-net pay computations, enforcing statutory deductions, and locking monthly payroll runs.

Main Features: Indian statutory compliance: PF (12% of Basic capped at ₹1,800/month), ESI (0.75% for gross < ₹21,000), Professional Tax (PT), and TDS withholdings; Loss of Pay formula ((Gross / Total Days) * LOP Days); instant payslip PDF generation via pdf-lib.

Dependencies: employee_salaries, payroll_runs, payslips, chart_of_accounts.

5. Employee Self-Service (ESS) Portal HRMS DB

Purpose: Self-service portal empowering employees to access personal data without admin dependency.

Responsibilities: Enabling clock-in/out, leave applications, attendance regularization, and document access.

Main Features: Dedicated isolated route at /employee; interactive punch widget with live stopwatch timer; leave balance tracker; payslip download archive; company document viewer.

Dependencies: JWT token claims with role: "employee", routes/ess.js.

6. CRM & Lead Pipeline (Kanban) CRM DB

Purpose: Commercial lead acquisition, qualification tracking, and sales cycle management.

Responsibilities: Lead ingestion, lead scoring, deal stage tracking, activity logging, and follow-ups.

Main Features: Drag-and-drop Kanban pipeline (New → Contacted → Qualified → Proposal → Negotiation → Won → Lost); scheduled follow-up reminders; 1-click conversion from Won Lead into active Customer record and linked onboarding Project.

Dependencies: crmPool, leads, customers, opportunities, crm_activities.

7. Sales Operations (Quotations, Orders & Invoices) CRM DB

Purpose: Commercial transaction generation, tax calculation, and payment lifecycle tracking.

Responsibilities: Price quotation authoring, sales order confirmation, and tax invoice generation.

Main Features: Line-item builder with tax rate calculations (GST/VAT); quotation revision history; sales order tracking; invoice status ledger (Draft, Issued, Partially Paid, Paid, Void).

Dependencies: quotations, sales_orders, crm_invoices, products, customers.

8. Finance, General Ledger & Expenses HRMS DB

Purpose: Comprehensive enterprise bookkeeping and cash flow tracking.

Responsibilities: Double-entry accounting, bank ledger reconciliation, and staff expense processing.

Main Features: Standard Chart of Accounts (COA); automatic journal entry creation linked to payroll runs and sales invoice payments; bank account reconciliation; staff expense claims with receipt image attachments.

Dependencies: accounts, general_ledger, bank_accounts, expense_claims.

9. Projects & Resource Delivery CRM DB

Purpose: Client delivery governance, milestone scheduling, and group collaboration.

Responsibilities: Tracking project scope, repository links, delivery phases, and team assignments.

Main Features: Project details view with repository URLs, budgets, and milestone progress; Resource Allocation Panel mapping staff to projects with percentage allocation and duration; team chat and phase workflows.

Dependencies: projects, project_allocations, project_groups, team_chat_messages.

10. Timesheets & Enterprise Task Board HRMS DB

Purpose: Daily operational task distribution and billable timesheet tracking.

Responsibilities: Task assignments, checklist verification, time logging, and manager approvals.

Main Features: Standalone weekly timesheet submission with project, task, and billable hour tagging; administrative timesheet review and approval workflow; enterprise task board with subtask checklists and file attachments.

Dependencies: timesheets, tasks, task_attachments, employees, projects.

7 System Workflow

The platform integrates commercial sales, operational delivery, human resource management, and financial accounting into an end-to-end continuous loop:

┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐ │ PHASE 1: REVENUE GENERATION (CRM & SALES) │ │ │ │ [Lead Generated] ──► [Kanban Stage Moves] ──► [Lead Marked 'Won'] │ │ (Marketing/Cold) (Qualified / Demo) │ │ │ ▼ │ │ [Invoice Issued] ◄── [Quotation / Order] ◄─── [Auto-Convert to Customer] │ │ (Payment Tracked) (Pricing & Scope) │ │ └─────────────────────────────────────────────────────┼──────────────────────────────────────────────────┘ │ Triggers Onboarding Project Creation ▼ ┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐ │ PHASE 2: PROJECT DELIVERY & OPERATIONS (ERP) │ │ │ │ [Project Created] ──► [Tasks Distributed] ──► [Employees Allocated] │ │ (Scope & Budget) (Checklists & Due) │ │ │ ▼ │ │ [QA Verification] ◄── [Milestones Met] ◄─── [Weekly Timesheet Logged] │ │ (Test Reports) (Progress Updated) │ │ └─────────────────────────────────────────────────────┼──────────────────────────────────────────────────┘ │ Correlated with Biometric Clock-In Logs ▼ ┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐ │ PHASE 3: HUMAN RESOURCES & PAYROLL (HRMS & FINANCE) │ │ │ │ [Daily Attendance]──► [Shift Adherence] ──► [Approved Leaves & LOP] │ │ (Biometric/Kiosk) (Late/Overtime) │ │ │ ▼ │ │ [General Ledger] ◄── [Payslip Delivered] ◄─── [Monthly Payroll Run] │ │ (Journal Entries) (PDF via ESS / Mail) (Statutory PF / ESI / TDS / PT Computed) │ └────────────────────────────────────────────────────────────────────────────────────────────────────────┘

Step-by-Step Lifecycle Description:

  1. Prospecting & Closing: Inquiries enter the CRM pipeline as Leads. Sales personnel record activities and advance deals through Kanban columns. When an opportunity is won, clicking "Convert" spawns a Customer record and creates a client Project.
  2. Resource Provisioning: Project Managers allocate developers and engineers to the project using the Allocation Panel, defining percentage allocation and timeframe. Tasks are assigned with subtask checklists.
  3. Time & Attendance Tracking: Staff log into the ESS portal or physical Kiosks to record daily attendance punches. Weekly billable hours are submitted through the Standalone Timesheet module for supervisor review.
  4. Payroll Computation & Ledger Posting: At the end of the pay cycle, HR executes the payroll run. The backend evaluates actual attendance against shift rosters, deducts Loss of Pay for unapproved leaves, applies statutory deductions (PF, ESI, PT, TDS), drafts locked payslips, and posts journal debits/credits directly into the General Ledger.

  • Backend: Executed natively with Node.js watch mode (npm run dev) on port 5000.
  • Frontend: Hosted on Vite development server with Hot Module Replacement on port 5173.
  • Databases: Hosted on local PostgreSQL service running on port 5432.

  • Orchestrated via docker-compose.yml exposing isolated container instances:
    • crm-frontend — Port 3001
    • crm-backend — Port 5001
    • hrms-db — PostgreSQL container on port 5434
    • crm-db — PostgreSQL container on port 5435

11.3 Production Deployment Topology

  • Reverse Proxy: Nginx handles SSL termination, HTTP/2 multiplexing, static asset caching, and rate limiting.
  • Process Manager: PM2 executes the Express backend in cluster mode (pm2 start index.js -i max), providing zero-downtime rolling reloads and automatic restarts on uncaught exceptions.
  • Database Cluster: Dedicated PostgreSQL 16 server with automated Write-Ahead Logging (WAL) archiving and scheduled nightly logical backups.

13 Known Limitations

13.1 Scalability Limits

In-Memory WebSocket Hub: The current real-time notification engine utilizes Node's built-in ws library within process memory. This efficiently handles up to 5,000 concurrent sockets on a standard single-server deployment. Beyond this threshold, an external message broker (such as Redis Pub/Sub) must be implemented to broadcast socket events across multi-instance worker processes.

Local File System Storage: File attachments (documents, task files, contracts) are written to backend/uploads/ on the host machine. Multi-server cloud deployments require transitioning to an object storage provider (e.g., AWS S3 or Cloudflare R2).

13.2 Technical Debt

  • Dual Module Format in Test Harness: While the application backend is authored in native ES Modules ("type": "module"), several test scripts in tests/ use CommonJS conventions.
  • Database Trigger Dependencies: Core attendance calculations and updated-at timestamps are governed by PL/pgSQL database triggers. While computationally fast, developers must inspect SQL migrations rather than application code to debug trigger-based updates.

13.3 Postponed Features

  • Native Mobile Applications: Currently delivered via a mobile-optimized responsive web interface (ESS). Dedicated native iOS/Android applications using React Native are planned for future versions.
  • In-App Video Conferencing: The recruitment module stores external meeting URLs (Google Meet/Zoom) rather than providing in-browser WebRTC video calls.

14 Maintenance Notes

14.1 Scheduled Operations

  • Daily Attendance Reconciliation (00:01 AM Cron): Evaluates punch logs against shift schedules and marks employees without clock-ins as "Absent".
  • Monthly Payroll Pre-Draft (25th of Month): Generates preliminary payroll calculations, incorporating attendance Loss-of-Pay deductions for HR review.
  • Weekly Database Maintenance: Executes VACUUM ANALYZE on PostgreSQL every Sunday at 02:00 AM to optimize query plans and reclaim storage.

14.3 Common Troubleshooting Playbook

Issue Encountered Likely Cause Immediate Remediation Steps
ECONNREFUSED 127.0.0.1:5432 PostgreSQL service inactive or credentials incorrect Start PostgreSQL service (systemctl start postgresql). Verify DB credentials in backend/.env.
ERR_MODULE_NOT_FOUND Missing dependency in node_modules Run npm install in the respective backend/ or frontend/ directory.
403 Forbidden: Module Not Permitted User lacks permission for requested module Assign the module to the user via Super Admin Settings or check the employee_module_assignments table.
WebSocket Connection Disconnected Reverse proxy dropping upgrade headers Ensure Nginx configuration includes proxy_set_header Upgrade $http_upgrade; and proxy_set_header Connection "upgrade";.
